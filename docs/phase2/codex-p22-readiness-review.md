## Verified safeguards

| Area | Finding |
| --- | --- |
| Public interfaces | Fixed HTTPS GET endpoints match [Lever's official Postings API](https://github.com/lever/postings-api) and [Ashby's public Job Postings API](https://developers.ashbyhq.com/docs/public-job-posting-api). Lever global/EU is a configuration enum. These document checks did not request employer feeds. |
| Allowlisting / SSRF | Empty board maps default to configuration-required. Configuration permits at most ten validated board IDs per source, rejects URL/path injection and case duplicates, and requires employer names. Requests cannot select arbitrary boards/URLs. Redirects are disabled; returned hosted posting/application links require the exact ATS host, configured board and consistent posting identity, and are never fetched. |
| Bounds | Decoded response cap 8 MiB; HTTP operation limit 15 seconds; at most two attempts for transport/5xx failures; no automatic retry for redirects, 401/403/404/429. Adapter deadline 75 seconds; execution deadline defaults to 90 seconds. At most 100 records selected per run. Pagination slices a full board response locally. |
| Authentication / cost | REST discovery requires the existing owner bearer boundary. Feed clients add no credentials or candidate data. Sources remain free/read-only/unverified; allowlists are empty by default. Existing paid-provider consent and budget gates remain. Source pacing is a durable local 60-second interval, not an asserted vendor quota. |
| Normalization / identity | Employer names come from operator mappings. Ashby unlisted jobs are excluded; remote/hybrid semantics and last-publication provenance match documentation. Unknown fields remain unknown; ambiguous salary groups are not asserted. Observation identity includes source and board, with Lever region in its namespace. Canonical URL and conservative company/content matching follow, with unique database guards. |
| Transactions / recovery | Durable idempotency claim precedes execution; changed requests with the same key conflict. Ingestion uses a transaction-scoped PostgreSQL lock and per-record savepoints. Successful batch writes and final audit commit together; individual rejected records can yield an explicit partial result. Exception/deadline rollback precedes an independent failure audit. Lost commit acknowledgement checks the durable finished audit before reporting failure. Unavailable failure auditing leaves a running claim that expires to recovery-required, without automatic replay. |
| Human state | Re-observation preserves job status, title, stored score/explanation and packet lifecycle/tracking/snapshot. Matching writes profile-version rankings to the run rather than replacing human job decisions. PostgreSQL regression tests exercise preservation. |
