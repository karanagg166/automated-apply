# Free platform capability and permission matrix

Research checked **2026-10-21**. Official sources below are documentation evidence, not owner
account entitlement or a live endpoint test. API/pricing/terms must be rechecked at activation.
“Unverified” deliberately means unavailable evidence; it does not assert that an API cannot
exist. No platform credentials, private API experiments or account logins were used.

## Reading the matrix

**S** supported documented operation; **C** conditional on permission/account entitlement;
**M** owner manual operation; **B** blocked for this plan. API scopes below are provider scopes,
not invented app variables. Setup: L = no credentials/selected source; M = owner consent/config;
H = partner contract or unresolved access. A publicly readable page does not establish automated
collection/retention permission. Robots directives cannot grant the missing rights.

For all rows: collect only relevant minimal evidence with source URL and observation time;
never infer missing salary, experience, size, contact accuracy or current availability. Restrict
private data to the owner, implement deletion/suppression, avoid indefinite raw HTML/email
retention. Provider contractual retention rules take precedence over proposed application TTLs.
Where no explicit archival license is established, keep links/minimal factual observations
and make automation conditional on source review. No bulk people database or republication.

## Closed platforms: actual account ownership is insufficient

No generic applicant OAuth scopes or rate quotas were verified for these platforms except
identity-only LinkedIn products. Default application action for every row is **manual on the
platform**. Their employer/ATS integrations do not let this agent apply as a jobseeker.
Manual reference capture/received alert extraction also needs source-content rights review;
Gmail OAuth alone does not grant republication rights over a platform's job descriptions.

Google's [2026 tools/API billing transition](https://developers.google.com/workspace/tools-safety)
makes “Google APIs are always unconditionally free” an unsafe assumption. Keep the OAuth project's
billing disabled, prohibit quota-increase/billing activation, monitor actual console limits and
set conservative application caps before activation. A budget notification is not a hard spend cap.

## Cost controls and integration review record

The default public-GET feeds have no account, card, paid overage path or trial expiry to activate.
They still have source availability/terms limits; configured refresh intervals are local safety
caps, not an SLA. Closed-platform API fees/free access/expiry remain unknown and excluded, not ₹0
claims. No owner registration is necessary on those platforms for synthetic development.

Each enabled source needs a record with operation, official docs/terms URL, checked date, account
entitlement (if any), rights/retention basis, scope, quota unit/window, estimated batch size,
free-only decision, expiry/review date, owner approval and actual verification receipt. Extend
`SourceConfig` and `integrations/registry.py`; reconcile the existing local capabilities JSON
rather than creating a contradictory second registry. Unknown permission or price => disabled.
Persist sanitized verification evidence/time separately from configured/available flags.

Suggested local ceilings (design values, **not published entitlements**): selected boards once/6h,
HN/Arbeitnow ≤4 refresh batches/day, Remotive ≤4/day, Gmail ≤20 alert bodies/sync with paging capped,
GitHub ≤20 selected repo requests/day, Telegram ≤20 relevant alerts/day plus one digest. Share
caps across workers via PostgreSQL; honor stricter source windows and Retry-After. Do not catch up
missed polling slots after sleep or make quota failures trigger an account upgrade.

Infrastructure/card/expiry details are canonical in [zero-cost architecture](zero-cost-architecture.md).
Owner workflows are in [account connection plan](real-account-connection-plan.md). Research does
not authorize any actual source read, mailbox ingestion, submission or notification activation.
